# monya

TUI-клиент для локального llama.cpp server, написанный на Go с использованием [Bubble Tea](https://github.com/charmbracelet/bubbletea).

Monya — это кото-ориентированный (мяу 🐾) терминальный интерфейс к локальному серверу, который умеет:

- хранить общий список чатов и профилей агентов;
- задавать каждому агенту system prompt;
- включать и выключать режим размышления отдельно для каждого чата;
- создавать несколько терминальных сессий и выбирать сессию для команд Monya;
- вести чат со стримингом ответов по SSE;
- отображать reasoning-контент модели отдельным блоком;
- выполнять bash-команды по запросу модели (tool calling) с подтверждением пользователем;
- сохранять историю диалога на диск между запусками;
- ограничивать частоту и параллельность запросов с retry/backoff.

## Требования

- Go 1.27.4 (см. `go.mod`)
- Запущенный llama.cpp server с OpenAI-совместимым API (по умолчанию `http://127.0.0.1:8080`)

## Сборка и запуск

Из корня репозитория:

```sh
go run ./cmd/monya
```

Или без сборки:

```sh
go build -o monya ./cmd/monya
./monya
```




### Флаги

| Флаг | Описание |
|------|----------|
| `-version` | напечатать версию и выйти |
| `-config <path>` | путь к `config.toml` (по умолчанию `~/.config/monya/config.toml`) |

## Конфигурация

Файл читается из `~/.config/monya/config.toml` (или по пути из `-config`).
Если файла нет — используются встроенные значения по умолчанию.

Для llama.cpp server с другой моделью или адресом создайте конфиг:

```toml
api_url = "http://127.0.0.1:8080"
default_model = "/home/idk/Models/Qwen3.5-4B-Q4_K_M.gguf"
default_agent = "dev-agent"
```

Отсутствующие поля подставляются из значений по умолчанию, невалидные (нулевые/отрицательные) — тоже.
Список чатов и агентов хранится отдельно от истории диалогов; endpoint `/v1/sessions` от llama.cpp не требуется.

## Управление

### Список чатов

| Клавиша | Действие |
|---------|----------|
| `↑` / `↓` | навигация |
| `/` | поиск по названию чата или агенту |
| `enter` | открыть чат |
| `n` | создать чат и выбрать агента (`←` / `→` или `tab`) |
| `d` | удалить чат и его историю (с подтверждением) |
| `a` | список агентов |
| `t` | терминальные сессии |
| `r` | перечитать сохранённый список |
| `q` | выход |

### Список агентов

| Клавиша | Действие |
|---------|----------|
| `enter` | изменить имя или system prompt |
| `n` | создать агента |
| `d` | удалить агента, если он не используется чатами |
| `esc` | список чатов |

В редакторе агента используйте `tab` для переключения между именем и system prompt, `ctrl+j` для новой строки и `ctrl+s` для сохранения.

### Экран чата

| Клавиша | Действие |
|---------|----------|
| `enter` | отправить сообщение |
| `ctrl+j` | перенос строки |
| `f3` | переключить thinking для этого чата; текущий статус показан цветным бейджем и сохраняется |
| `f4` | переключить доверенное выполнение для этого чата; статус сохраняется |
| `ctrl+t` | выбрать активный терминал |
| `pgup` / `pgdown` | прокрутка истории |
| `esc` | отмена стрима или возврат к списку чатов |
| `ctrl+y` | скопировать последний ответ ассистента |
| `ctrl+b` | скопировать последний блок кода из ответа |
| `ctrl+c` | прервать выполняющуюся команду; если команда не выполняется — выход |

### Выполнение команд

По умолчанию Monya показывает команду `run_bash` и ждёт решения:

- `enter` / `y` — выполнить;
- `n` / `esc` — отклонить (модель получит сообщение о запрете);
- при превышении 30 секунд появляется выбор: `k` — убить процесс, `w` — подождать.

`f4` включает доверенное выполнение для текущего чата. Простые `pwd`, `cd`, `ls`, `cat`, `grep`, `rg`, `head`, `tail`, `wc`, `stat`, `file`, `whoami`, `date` и `uname` запускаются без подтверждения. Для `sed` автоматически разрешены только простые операции чтения/вывода/замены; запись в файлы (`-i`) и другие sed-скрипты не запускаются автоматически. Команды с shell-операторами не относятся к безопасным.

Другие простые команды сначала требуют подтверждения. Если доверенное выполнение включено, подтверждение запоминает **точную строку команды** в `~/.config/monya/approved_commands.json`; повтор той же строки запускается автоматически. Изменение аргументов считается другой командой и снова требует подтверждения. Команды с shell-операторами, кавычками или подстановками выполняются только после подтверждения и не запоминаются. При выключенном режиме сохранённые разрешения не используются — все команды спрашиваются.

Вывод команды обрезается до 16 KiB и отправляется обратно модели как результат tool-вызова.

### Файловые инструменты агента

Агент может использовать `read_file` и `create_file` без подтверждения. Оба инструмента ограничены каталогом, из которого запущена Monya, и принимают только относительные пути. `read_file` работает с UTF-8-файлами размером до 1 MiB; по умолчанию возвращает до 120 строк, максимум — 500 строк за вызов. `create_file` создаёт родительские каталоги и новый файл размером до 1 MiB, но никогда не перезаписывает существующий.

### Терминалы

| Клавиша | Действие |
|---------|----------|
| `s` | выбрать текущий терминал для Monya и вернуться, не открывая консоль |
| `enter` | открыть консоль; терминал также становится активным |
| `n` | создать терминал |
| `d` | закрыть терминал (с подтверждением) |
| `r` | перезапустить недоступный терминал |
| `esc` | вернуться в чат |

В терминале вводите команды и нажимайте `enter`; состояние shell, включая `cd` и переменные, сохраняется между командами. Если запущенная команда ждёт ввод, введите строку и нажмите `enter`. Сессии живут до выхода из Monya. Это встроенная построчная консоль, а не полноценный эмулятор TTY: полноэкранные программы вроде `vim` не поддерживаются.

Чтобы выбрать терминал, не открывая его: нажмите `ctrl+t` в чате, выделите сессию стрелками и нажмите `s`. Активный терминал отображается в списке чатов и в постоянной строке чата вместе с режимом thinking; tool-команды Monya выполняются именно в выбранной сессии.

## Структура проекта

```
cmd/monya/main.go         точка входа: флаги, конфиг, сборка клиента и TUI
internal/config/          загрузка и дефолты config.toml
internal/api/             OpenAI-совместимый API-клиент, типы запросов/ответов, SSE-стриминг
internal/ratelimit/       http.RoundTripper: лимит rps, конкурентность, retry на 429/5xx
internal/store/           сохранение профилей агентов, списка чатов и историй в JSON
internal/terminal/        постоянные bash-сессии для пользователя и tool-вызовов
internal/tui/             Bubble Tea-модель интерфейса
```

## Как это работает

1. Профили и список чатов сохраняются в `~/.local/share/monya/workspace.json`; история каждого чата — в `~/.local/share/monya/chats/`.
2. При первом запуске старые истории из `~/.local/share/monya/history/<agent>.json` импортируются как чаты и остаются на месте.
3. System prompt выбранного агента и состояние thinking чата добавляются к запросу.
4. Перед отправкой Monya считает размер истории через llama.cpp и при необходимости убирает из запроса старые целые ходы, оставляя исходную историю на диске; для ответа резервируется до 1024 токенов.
5. Сообщение отправляется через `POST /v1/chat/completions` с `stream: true`.
6. Ответ читается как SSE-поток: `content`, `reasoning_content` и `tool_calls` накапливаются по дельтам.
7. Если в ответе есть tool call — интерфейс ждёт подтверждения и выполняет команду в выбранной shell-сессии.
8. Результат добавляется в историю как сообщение с ролью `tool`, и стрим запускается заново. `cd` и переменные shell сохраняются для следующих команд.

Запросы генерации проходят через `internal/ratelimit.Transport`, который:

- ограничивает конкурентность семафором;
- ждёт разрешения у `golang.org/x/time/rate.Limiter`;
- повторяет запросы при сетевых ошибках, `429` и `5xx` (до 3 попыток, экспоненциальный backoff, уважает `Retry-After`).

Локальные запросы к `/props`, `/apply-template` и `/tokenize` используются для контроля контекста и не ограничиваются рейт-лимитером.
